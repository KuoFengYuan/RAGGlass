## 上傳含原生文字的 PDF

工作台與文件庫會顯示目前設定的兩項限制：預設每份 PDF **30 MB、200 頁**。整份文件沒有字數上限。按**上傳 PDF**選檔後，瀏覽器先檢查容量和 PDF 標頭，再用 PDF.js 開啟文件、檢查頁數與加密，並尋找可選取文字，通過後才傳給 API。**正在檢查 PDF…**與**正在上傳 PDF…**會區分目前步驟並顯示檔名。不合格文件會說明如何修正，不會建立文件紀錄或啟動文件模型。

API 也會獨立檢查容量、PDF 是否有效、加密、頁數與原生文字，包含繞過介面直接呼叫的請求。PDF 檢查在 API 事件迴圈以外執行。成功回應後文件立即排入處理；等待時已可閱讀原始 PDF。重複上傳相同位元內容會沿用原文件 ID 與索引；若原文件已停止或失敗，需按**重新索引**才能再次處理。

原生文字檢查只是前置檢查，不代表每一頁都能成功解析。含部分可選取文字的混合 PDF 可通過；只有圖片的頁面不會自動執行 OCR。此版拒絕找不到原生文字的文件，仍未支援 OCR／VLM。

## 查看處理進度

文件面板會顯示**等待處理**、**解析中**、**切塊中**、**向量化中**或**索引中**，以及已耗用時間。排隊時顯示等待時間；工作執行緒接手後才開始計算處理耗時。切塊完成後顯示：

- **已向量化 X / N**：已完成向量運算的片段數。
- **已寫入索引 Y / N**：已取得 Qdrant 寫入確認的片段數。進度條代表已寫入片段比例，不是解析或整體耗時的完成百分比。

每批完成後，向量化與索引階段會交替出現。解析階段只顯示狀態與實際經過時間，不估算百分比或剩餘時間。處理中的文件約每 750 毫秒更新；一般工作空間／服務狀態維持每四秒更新。重新整理頁面會讀取已保存狀態，不另行提交作業。文件庫的處理中項目也會顯示已寫入／總片段數。

文件詳情保存排隊／開始／結束時間、實際批次大小、進度、設定與各階段耗時。向量化與索引耗時加總所有批次；`total` 計算處理時間，`queue_wait` 另行保存。此功能加入前的文件仍可閱讀，重新索引後會補上新欄位。

## 停止或重試

按**停止處理**。排隊中的作業可立即取消；執行中的作業會顯示**正在停止…**，等目前 CPU 或 Qdrant 操作結束後，在下一個操作／批次前停止。Docling 轉換無法中途打斷，因此解析中的停止可能需要等完整剩餘轉換時間。工作執行緒真正結束前，清理與重新索引的保護仍會生效。

完成後狀態為**已取消**。原始 PDF、已完成的解析產物、已保存片段，以及取得確認的部分向量寫入都保留供檢查。取消或失敗的文件不能查詢；進度數字代表已完成工作，不代表有完整可用索引。後端在查詢開始時仍只接受已索引文件；停止或重新索引不會改寫歷史查詢的證據。

按**重新索引**可重新處理原始 PDF。此操作重跑完整流程、重設進度，只初始化目前 collection 一次，移除這份文件的舊向量後重新建立完整索引，不會從檢查點續跑。已停止的文件也可使用既有清理功能明確刪除；停止本身不會刪除 PDF 或查詢紀錄。

API 正常關閉會要求停止作業，等待目前操作結束。若突然中斷，啟動時會將未完成作業標為失敗，供使用者明確重新索引。已取消紀錄的狀態與進度會在重啟後保留。這仍是本機、單一工作執行緒的佇列，不是分散式背景作業服務。

## 設定有界的向量批次

啟動 API 前可在 `.env` 設定：

```dotenv
MAX_UPLOAD_MB=30
MAX_PDF_PAGES=200
INGEST_BATCH_SIZE=32
```

`INGEST_BATCH_SIZE` 接受 **1–256 個片段**，預設 **32**。每個外層批次以既有每次 16 段的模型批次運算，取得 Qdrant 寫入確認後釋放向量，再處理下一批。因此保留的向量結果數量由批次設定決定，不隨整份片段數增加。這不代表 Docling 解析、全部文字／片段 metadata 或上傳都改成串流，也不宣稱已量測到整個程序峰值記憶體下降。較大批次可能用更多記憶體、增加停止等待，以換取較少寫入次數，需使用自己的文件量測。更改這項批次值不會改變 embedding 空間指紋，不需要進行 embedding 模型遷移。

## 重現驗證

```bash
bash scripts/check.sh
.venv/bin/python scripts/verify_ingestion.py --browser
```

驗證程式建立自己的暫存 loopback API 與 `qdrant/qdrant:v1.15.5` 容器，重用既有模型 HTTP 服務，完成後清除自己的服務。檢查上傳及早拒絕、實際分批寫入與數量、排隊與執行中的取消、重啟、虛構 CC0 24 頁變體完整重新索引、六題真實模型問題、瀏覽器前置檢查／停止／重試，以及既有閱讀／查詢／清理流程。執行前後比較擁有者文件／SQLite 檔案雜湊；量測與日誌只保留於 Git 忽略的 `.data/ingestion-*`。

Python 合成契約測試另外檢查批次間向量生命週期、停止邊界、異動保護、失敗與關閉服務。瀏覽器測試會明確標示模擬的進度 metadata；PDF 開啟與本機前置檢查使用真正的 PDF.js。六題範例與重複文件屬於基本流程／壓力檢查，不是檢索品質 benchmark 或大型語料效能宣稱。已實際執行的結果請見里程碑紀錄。
